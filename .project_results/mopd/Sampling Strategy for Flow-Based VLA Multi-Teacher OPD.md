# Sampling Strategy for Flow-Based VLA Multi-Teacher OPD

## 1. Problem Setup

We consider a flow-based VLA Multi-Teacher On-Policy Distillation (MOPD) setting with:

- **3 task suites**
- Each suite contains multiple concrete tasks
- Each concrete task generates the **same number of rollout trajectories**
- Different tasks may produce different numbers of valid states/action chunks because their trajectory lengths differ
- Each suite should receive **equal training weight**

The sampling hierarchy is:

\[
\text{Suite}
\rightarrow
\text{Task}
\rightarrow
\text{Trajectory}
\rightarrow
\text{State / Action Chunk}
\rightarrow
\text{Flow Timestep } \tau
\]

---

# 2. Main Setting

## Suite-Balanced Training + Natural Within-Suite State Sampling

### Rollout Collection

Within each suite, every concrete task generates the same number of rollout trajectories:

\[
M_{s,1}=M_{s,2}=\cdots=M_{s,K_s}.
\]

Therefore, concrete tasks are already balanced at the **trajectory-exposure level**.

### Suite-Level Training Balance

The three suites receive equal optimization budget:

\[
P(s)=\frac{1}{S}.
\]

For three suites:

\[
P(s)=\frac13.
\]

### Within-Suite Sampling

For suite \(s\), pool all valid rollout states/action chunks:

\[
\mathcal B_s
=
\bigcup_{k=1}^{K_s}\mathcal B_{s,k}.
\]

Then naturally sample:

\[
x\sim U(\mathcal B_s).
\]

No additional task-level reweighting is applied.

Thus, if two tasks have the same number of rollout trajectories but different trajectory lengths, the longer task naturally contributes more training states.

For example:

| Task | Rollouts | Valid States |
|---|---:|---:|
| Task A | 100 | 5k |
| Task B | 100 | 20k |

The rollout exposure is:

\[
A:B=1:1,
\]

while the state-level training contribution is naturally:

\[
A:B=1:4.
\]

This preserves the student's natural on-policy state occupancy within each suite.

### Flow-Time Sampling

After sampling an environment state/action chunk:

\[
\tau\sim p(\tau),
\]

using the same flow-time sampling strategy as the original OPD method.

### Main Objective

Conceptually:

\[
\boxed{
s\sim U(\mathcal S),
\qquad
x\sim U(\mathcal B_s),
\qquad
\tau\sim p(\tau)
}
\]

with task-balanced rollout collection:

\[
M_{s,k}=M_s.
\]

### Interpretation

> **Equal optimization budget across suites, equal rollout exposure across tasks, and natural on-policy state occupancy within each suite.**

This is the main setting.

---

> **Implementation notes and review:** [PLAN_state_coverage.md](PLAN_state_coverage.md).
> Two review points change what gets built or how results are read: `P(s)=1/3` should be
> realised by importance weighting rather than resampling (at full scale the atomic suite
> would otherwise be duplicated 2.54x), and long episodes are disproportionately *failures*
> because a successful episode terminates early — so natural within-suite sampling weights
> failed-episode states most heavily.

# 3. Ablation Studies

## A0. Truncated-Horizon Collection *(added in review)*

Collect rollouts with every episode truncated at a fixed short budget (the current setting,
320 steps) instead of running each task's native horizon, and sample from those.

At 320 steps the covered fraction of a trajectory is 71% for the atomic tasks but only 19-27%
for the composite ones, so the student is distilled on the first quarter of a trajectory and
evaluated on all of it.

### Question

> **Does full-horizon state coverage matter at all?**

This is a change to *rollout collection* rather than to the sampling distribution, so it sits
outside the Suite/Task/Episode/State hierarchy — but it is the comparison that justifies
rebuilding the sampler, and without it none of A1-A4 can be attributed to sampling rather than
to coverage. Run it against the Main setting at an equal env-step budget: the sample count is
invariant at a fixed budget, so the only difference is coverage against episode diversity
(~20 long episodes per epoch versus ~64 short ones).


## A1. Fully Natural Sampling

Pool all rollout states from all suites:

\[
\mathcal B
=
\mathcal B_1
\cup
\mathcal B_2
\cup
\mathcal B_3,
\]

and sample:

\[
x\sim U(\mathcal B).
\]

Therefore:

\[
P(s)
=
\frac{N_s}{\sum_jN_j},
\]

where \(N_s\) is the number of valid states/action chunks generated by suite \(s\).

### Question

> **Is explicit suite-level balancing necessary?**

### Comparison with Main

- **Fully Natural:** suite weight is determined by total generated states.
- **Main:** every suite receives equal training budget.

This should be the most important baseline against the main setting.

---

## A2. Task-Balanced State Sampling

Keep suites balanced:

\[
P(s)=\frac1S.
\]

Within each suite, explicitly sample concrete tasks uniformly:

\[
P(k|s)=\frac1{K_s},
\]

then sample a state/action chunk from that task:

\[
x\sim U(\mathcal B_{s,k}).
\]

Therefore, each concrete task receives equal optimization budget regardless of trajectory length.

### Question

> **Should longer tasks naturally receive more OPD updates because they contain more on-policy decision states?**

### Comparison with Main

Suppose:

\[
N_A=5k,\qquad N_B=20k.
\]

Main:

\[
A:B=1:4.
\]

Task-balanced:

\[
A:B=1:1.
\]

This is the second most important ablation.

---

## A3. Tempered Task Sampling

Introduce an intermediate task-level sampling distribution:

\[
P(k|s)
=
\frac{N_{s,k}^{\alpha}}
{\sum_j N_{s,j}^{\alpha}}.
\]

A useful choice is:

\[
\alpha=0.5.
\]

This creates an interpolation between strict task balancing and natural state weighting:

\[
\alpha=0
\quad\rightarrow\quad
\alpha=0.5
\quad\rightarrow\quad
\alpha=1.
\]

Interpretation:

- \(\alpha=0\): concrete tasks are strictly equal
- \(\alpha=0.5\): partially preserve differences in state count
- \(\alpha=1\): proportional to natural state count

Importantly, the **main method itself does not need to be described using this formulation**. The \(N_k^\alpha\) formulation is only used as an ablation.

### Question

> **Is there a better compromise between strict task balance and natural on-policy state occupancy?**

---

## A4. Episode-Balanced Sampling

Use the hierarchy:

\[
\text{Suite}
\rightarrow
\text{Task}
\rightarrow
\text{Episode}
\rightarrow
\text{State}.
\]

Specifically:

\[
s\sim U(S),
\]

\[
k\sim U(K_s),
\]

\[
e\sim U(E_{s,k}),
\]

\[
x\sim U(\mathcal B_{s,k,e}).
\]

Every rollout trajectory therefore contributes equal total training weight regardless of its length.

For example:

- Episode A: 40 states
- Episode B: 200 states

Main setting gives approximately:

\[
A:B=1:5
\]

state-level contribution.

Episode-balanced sampling gives:

\[
A:B=1:1.
\]

### Question

> **Should longer trajectories contribute proportionally more OPD supervision?**

This ablation is particularly useful for checking whether long failure/timeout trajectories dominate training.

# 5. Recommended Priority

If computational budget is limited, prioritize:

### Core experiments

1. **Main**
2. **A1 — Fully Natural**
3. **A2 — Task Balanced**

These directly compare:

\[
\boxed{
\text{No balancing}
\rightarrow
\text{Suite-level balancing}
\rightarrow
\text{Suite + task-level balancing}
}
\]

This provides the cleanest methodological story.

### Additional experiments

4. **A3 — Tempered task sampling**
5. **A4 — Episode-balanced sampling**

These investigate whether partial task rebalancing or trajectory-length normalization provides additional benefits.

---

# 6. Variables That Should Remain Fixed

Across all sampling ablations, keep the following unchanged:

- Number of rollout trajectories per concrete task
- Teacher routing
- Student policy initialization
- Total training/update budget
- Batch size / total sampled state budget
- Optimizer and learning rate
- Flow timestep distribution \(p(\tau)\)
- Flow-matching / OPD loss formulation
- Environment and evaluation settings

This ensures that performance differences can be attributed specifically to:

\[
\boxed{
\text{how MOPD optimization budget is allocated across suites, tasks, and trajectories}
}
\]

---

# 7. Main Takeaway

The proposed main setting is:

\[
\boxed{
\textbf{Suite-balanced training}
+
\textbf{task-balanced rollout collection}
+
\textbf{natural on-policy state sampling within each suite}
}
\]

It deliberately balances high-level suite capabilities while preserving the natural state occupancy induced by the student policy within each suite.

The core ablation question is therefore:

\[
\boxed{
\text{At which level of the task hierarchy should MOPD optimization budget be explicitly balanced?}
}
\]

The main method balances only at the **suite level**, while the ablations progressively remove or extend this balancing assumption.
